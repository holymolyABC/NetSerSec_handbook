# 구형 Linux의 시간·시간대 점검

**대상:** 레거시 Red Hat 계열 운영 사례. 시간대 오류와 실제 시계 오차를 구분합니다. 새 NTP 설치 가이드는 아닙니다.

## 1. 조회

```bash
date '+%Y-%m-%d %H:%M:%S %Z %z'
date -u
hwclock --show
cat /etc/sysconfig/clock
cat /etc/adjtime
rpm -qa | egrep '^(ntp|chrony)'
ps -ef | egrep '[n]tpd|[c]hronyd|[n]tpdate'
```

| 결과 | 해석 |
|---|---|
| KST +0900, Asia/Seoul | 한국 시간대 설정 |
| UTC=true, adjtime의 UTC | 하드웨어 시계를 UTC 기준으로 관리. 이 값 자체는 정상 |
| hwclock --show | 통상 현지 시간으로 변환해서 표시. 저장 형식을 KST로 단정하지 않음 |
| ntpq 없음 | 그 도구가 없다는 뜻. 모든 시간 동기화 부재를 확정하지 않음 |
| ntp/chrony 패키지·프로세스 없음 | 표준 동기화가 확인되지 않음. 독자 cron·가상화·관리 계층은 별도 확인 |

필요하면 cron과 관리 계층의 시간 동기화도 조사하되 기밀 설정을 그대로 공유하지 않습니다.

## 2. 수동 보정 — 변경 단계

**[주의: 서비스 영향 가능]** 큰 시각 변경은 로그·cron·인증·TLS·DNSSEC 등에 영향을 줄 수 있습니다. 기준 시계·오차·실시 시각과 의존 서비스를 확인하고 변경 전 시각을 남깁니다.

아래 값은 실행 시점의 정확한 한국 시간으로 모두 치환합니다. 과거 예제 시간을 그대로 입력하지 않습니다.

```bash
date -s "YYYY-MM-DD HH:MM:SS"
date '+%Y-%m-%d %H:%M:%S %Z %z'
```

시스템 시각이 정확한지 확인한 다음, UTC로 관리하는 환경에서만 RTC에 저장합니다.

```bash
hwclock --systohc --utc
hwclock --show
```

잘못된 시각을 RTC로 복사하지 않습니다. 잘못 보정했다면 정확한 현재 시각으로 재보정하며, 기계적으로 과거 값으로 되돌리지 않습니다. 기존 로그는 수정하지 않고 시간 역전 여부를 기록합니다.

## 3. 재발 방지

기관 지정 NTP 서버·경로·OS 지원 클라이언트·RTC 정책을 확인합니다. 임의의 외부 시간 서버를 등록하지 않습니다. 동기화 서비스, 선택된 서버, 오프셋과 지속적인 변화를 검증합니다.
