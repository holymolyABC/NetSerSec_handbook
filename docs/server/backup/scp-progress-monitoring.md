# SCP 백업 중 파일 크기 실시간 확인

대상: Linux 수신 서버, `watch` 및 GNU `ls`·`stat` 사용 환경  
상태: 예시 — 운영 서버의 실행 결과는 확인 필요  
검토일: 2026-10-16 (Asia/Seoul)

## 목적과 적용 범위

이미 실행 중인 SCP 전송을 중단하지 않고, 수신 중인 파일 크기를 2초마다 확인한다. 이 명령 자체는 진행률(%), 전송 속도, 남은 시간을 계산하지 않는다.

이 문서의 `/backup/backup.tar.gz`는 예시 경로다. 실제 **수신 대상 파일 경로**로 바꾼다. 원본 서버에서 원본 파일을 조회하면 전송 진행 상태를 알 수 없다.

## 사전 조건과 영향

- 파일을 받는 서버에 별도 SSH 세션 또는 터미널을 연다. SCP가 실행 중인 터미널은 그대로 둔다.
- 조회 계정에 대상 디렉터리 접근 권한과 파일 메타데이터 조회 권한이 필요하다.
- `watch` 설치 여부는 `command -v watch`로 확인한다. 옵션은 해당 서버의 `man watch`를 우선한다.
- 아래 명령은 메타데이터 조회이며 파일 내용·설정·전송 프로세스를 변경하지 않는다. 별도 백업이나 변경·롤백은 필요하지 않다.

## 1. 2초마다 파일 크기 확인

수신 서버의 별도 터미널에서 실행한다.

```bash
watch -n 2 'ls -lh /backup/backup.tar.gz'
```

| 구성 | 의미 |
|---|---|
| `watch` | 명령을 반복 실행하여 화면 갱신 |
| `-n 2` | 갱신 간격을 2초로 지정 |
| `ls -l` | 크기·권한 등 파일 상세 정보 표시 |
| `-h` | 크기를 K·M·G 등 읽기 쉬운 단위로 표시 |
| 작은따옴표 | 반복 실행할 명령을 하나로 묶음 |

출력 예시이며 실서버 출력은 아니다.

```text
-rw-r--r-- 1 backup backup 1.5G Oct 16 19:20 /backup/backup.tar.gz
```

크기가 `1.5G → 1.6G → 1.7G`처럼 증가하면 대상 파일에 데이터가 기록되고 있다는 근거가 된다.

변경된 부분을 강조하려면 다음 명령을 사용한다.

```bash
watch -d -n 2 'ls -lh /backup/backup.tar.gz'
```

## 2. 크기가 그대로일 때 더 정확하게 확인

`ls -lh`는 반올림해서 표시하므로 소량씩 증가하면 화면상 크기가 같아 보일 수 있다. GNU stat이 있는 Linux에서는 바이트 단위로 확인한다.

```bash
watch -n 2 'stat -c "%n : %s bytes" /backup/backup.tar.gz'
```

전송 시작 전에 크기가 확정된 원본 파일이라면, 같은 단위로 측정한 크기로 대략적인 진행률을 계산할 수 있다.

```text
진행률(%) ≈ 수신 파일 크기(바이트) ÷ 원본 파일 크기(바이트) × 100
```

예: 원본 10,000,000,000바이트, 수신 파일 6,000,000,000바이트 → 약 60%. 원본이 계속 생성·변경되는 파일이면 이 계산을 완료율로 사용하지 않는다.

## 3. 결과 해석과 다음 단계

| 관찰 결과 | 해석 및 다음 단계 |
|---|---|
| 크기가 계속 증가 | 수신 파일 기록 진행 중. 전송 완료 여부는 별도 확인 |
| K·M·G 표시가 잠시 동일 | 반올림 영향 가능. 바이트 단위로 확인 |
| 바이트 크기도 계속 동일 | 완료·전송 정체·오류 가능. SCP 터미널 메시지와 종료 상태 확인 |
| `No such file or directory` | 수신 서버·경로·파일명 확인. 아직 해당 파일 전송이 시작되지 않았을 수도 있음 |
| `Permission denied` | 조회 계정의 경로 접근 권한 확인 |
| `watch: command not found` | watch 미설치. 별도 설치 없이 아래 반복 조회 사용 가능 |

`watch`가 없을 때는 별도 터미널에서 다음과 같이 조회한다.

```bash
while true; do
    ls -lh /backup/backup.tar.gz
    sleep 2
done
```

## 4. 조회 종료와 전송 완료 검증

- **조회 터미널에서 `Ctrl+C`**를 눌러 watch 또는 반복문을 종료한다. 별도 세션에서 실행 중인 SCP 전송은 계속된다.
- **SCP가 실행 중인 터미널에서 `Ctrl+C`를 누르면 전송이 중단될 수 있다.** 터미널을 구분한다.
- 파일 크기가 멈추거나 원본과 같아진 것만으로 백업 성공을 확정하지 않는다.
- SCP가 종료된 뒤, 실행한 셸에서 다른 명령을 실행하기 전에 `echo $?`로 종료 코드를 확인한다. 0은 SCP 정상 종료, 0 이외는 오류다. 스크립트 내부 SCP 결과는 그 스크립트에서 별도로 기록해야 한다.
- 전송 후 필요에 따라 원본·대상 체크섬 비교와 백업 복원 검증을 수행한다. 전송 성공과 DB 백업 정합성·복원 성공은 별개다.

## 한계와 검증 범위

- 이 절차는 단일 수신 파일의 크기 관찰이다. 폴더 전체의 진행률이나 정확한 ETA를 제공하지 않는다.
- 크기 증가는 기록 활동을 나타내지만 실제 디스크 영구 저장이나 복원 가능성을 보장하지 않는다.
- GNU `stat -c`는 macOS·BSD의 stat과 문법이 다르다.
- 공식 매뉴얼 대조 및 문서 정적 검토를 수행했다. 실제 운영 서버에서의 전송·복원 검증은 수행하지 않았다.
