# 상위 위임·네임서버·등록기관 점검

**목적:** zone 내부 NS와 상위 등록을 구분하고, 응답하지 않는 DNS로 인해 이름 해석이 불안정한지 확인합니다. 상위 등록 변경은 서버 파일 편집과 별도 작업입니다.

| 정보 | 관리 위치 | 의미 |
|---|---|---|
| A 레코드 | 자사 권한 zone | 호스트의 IPv4 주소 |
| zone 내부 NS | 자사 권한 zone | 이 zone의 권한 서버 |
| 부모의 위임 NS | 상위 DNS, 보통 등록기관 경유 | 어느 권한 서버에 질문할지 안내 |
| glue | 부모의 추가 주소 정보 | 위임 서버 이름의 주소 확인을 보조 |

zone 내부에서 NS를 주석 처리해도 부모의 등록은 자동 변경되지 않습니다. 웹서버 동작과 DNS 동작도 별개입니다.

## 1. 현재 위임 경로 확인

```bash
dig +trace example.org. NS
dig @192.0.2.234 example.org. NS +norecurse
```

trace에서 실제로 확인된 부모 권한 DNS의 이름/IP를 사용합니다. 다음 PARENT_DNS_IP는 반드시 치환합니다.

```bash
dig @PARENT_DNS_IP example.org. NS +norecurse
```

부모 응답의 AUTHORITY SECTION과 필요한 ADDITIONAL을 읽습니다. 옛 대화의 상위 IP를 무조건 고정해 사용하지 않습니다.

## 2. 각 권한 DNS 검증

등록된 각 IP에 A·SOA·NS와 UDP/TCP 53을 직접 질의합니다. ping 불통만으로 폐기 여부를 판단하지 않습니다. 서비스 중지·FW·경로와 실제 미사용을 구분합니다.

## 3. 변경과 검증

미사용을 확인한 네임서버는 등록기관에서 정리하고 필요한 glue도 맞춥니다. 변경 전후 목록과 복원 방법을 남깁니다. 웹용 A 레코드나 웹 방화벽 정책을 함께 삭제하지 않습니다.

변경 후 부모·자식 NS, 각 권한 서버 SOA serial, 외부 재귀 리졸버의 결과를 비교합니다. 부모 정보에도 캐시가 있어 즉시 전체 반영을 약속하지 않습니다. 단일 권한 DNS에 의존한다면 독립된 장애 범위의 이중화를 계획합니다.
