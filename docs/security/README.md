## 외부 DNS 요청 대응 순서

1. 정상 권한 조회를 유지하며 [재귀·캐시 ACL](../dns/04-access-control.md)을 제한합니다.
2. 로그·FW세션·요청량·CPU/I/O로 실제 영향을 측정합니다.
3. 필요하면 특정IP의 기한부 차단과 장비의DNS DoS·요청량 제한을 검토합니다.
4. [로그 분리·용량 제한](../dns/05-logging.md)을 설정합니다. 기록 위치 변경은 트래픽 차단이 아닙니다.

**[주의: 서비스 영향 가능]** 정상 요청도 세계 여러 리졸버에서 옵니다. 국가별·광범위 차단이나 너무 낮은 한도는 정상 사용자 조회를 끊을 수 있습니다. UDP위조도 고려하여 관찰된 모든IP를 자동 영구 차단하지 않습니다.

특정IP를 막는 경우 해당IP→권한DNS의UDP/TCP53으로 범위를 한정하고, 기존 허용 정책보다 먼저 적용되는지 장비 방식에 맞춰 확인합니다. 변경 전hit와 변경 후 정상 외부 조회를 비교합니다. 롤백은 해당 차단 정책 비활성화입니다.

외부53번 전체나TCP53 일괄 차단을 영역 전송 제어의 대체 수단으로 사용하지 않습니다. L4포트 변환만으로 앱의 공개URL·리다이렉트가 모두 고쳐진다고 가정하지 않습니다.
